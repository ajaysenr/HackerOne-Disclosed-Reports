## Vulnerability Details

## Summary

The `POST /Umbraco/Api/ContactApi/SaveAttachment` endpoint on both `████████` and `████████` allows unauthenticated file uploads without CAPTCHA, without rate limiting, and with a CORS `access-control-allow-origin: *` header. This combination allows any website on the internet to silently upload malicious files (including PDFs with embedded JavaScript) to Essity's backend storage.

## Affected Assets

- `https://████████/Umbraco/Api/ContactApi/SaveAttachment`
- `https://████████/Umbraco/Api/ContactApi/SaveAttachment`

## Steps To Reproduce

### 1. Basic unauthenticated file upload (PNG)

```bash
# Create a minimal valid PNG
printf '\x89PNG\r\n\x1a\n' > /tmp/test.png

# Upload without any authentication
curl -sk -X POST 'https://████████/Umbraco/Api/ContactApi/SaveAttachment' \
  -H 'X-Requested-With: XMLHttpRequest' \
  -F 'file=@/tmp/test.png;type=image/png;filename=test.png'
```

**Expected:** Error or authentication required
**Actual:** `["2e1ab0fe-db41-45ee-ad63-954edf814f77_test.png"]` (file stored successfully)

### 3. CORS wildcard verification (cross-origin upload from any domain)

```bash
# Preflight check from evil origin
curl -sk -X OPTIONS 'https://████████/Umbraco/Api/ContactApi/SaveAttachment' \
  -H 'Origin: https://evil.attacker.com' \
  -H 'Access-Control-Request-Method: POST' \
  -H 'Access-Control-Request-Headers: X-Requested-With'
```

**Response headers include:**
```
access-control-allow-origin: *
```

This means any website can upload files via JavaScript fetch/XMLHttpRequest.

## Impact

An attacker can abuse this vulnerability to:

1. **Deliver malicious PDFs to Essity staff:** When backoffice staff reviews contact form submissions and opens the attached PDF, the embedded JavaScript executes in Adobe Reader context. This can be escalated to:
   - `app.launchURL()` for phishing attacks
   - FormCalc `url.loadFile()` for local file exfiltration from the staff workstation
   - In browser-based PDF viewers: potential XSS in the backoffice origin

2. **Storage Denial of Service:** With no authentication, no rate limit, and 14MB max file size, an attacker can write ~50GB/hour to Essity's storage from a single IP. With parallelism: unlimited. Cost to attacker: zero.

3. **Cross-Origin Exploitation:** The CORS wildcard means an attacker only needs to get any Essity employee (or any internet user) to visit their page. The upload happens silently in the background, requiring zero user interaction beyond visiting an attacker-controlled page.

## Remediation

1. Require authentication (session cookie) for file uploads
2. Implement server-side reCAPTCHA validation
3. Add rate limiting (e.g., max 3 uploads per IP per minute)
4. Scan uploaded files for malicious content (PDF JS, polyglots)
5. Replace `access-control-allow-origin: *` with specific allowed origins
6. Implement file size quota per session/IP
