## Vulnerability Details

**Type:** Denial of Service (Availability)
**Severity:** Low-Medium (CVSS 3.7-5.5 depending on access)
**Affected:** WeblateOrg/translation-finder v3.4.1, commit f5f8bb5 (current main)

## TL;DR

`translation-finder` scans repository content using recursion without any depth limit. A repository with ~1000 nested folders causes an uncaught `RecursionError` that crashes the entire discovery call. The error is not handled anywhere, so Weblate's import/update/hook processing fails repeatedly.

## Tested environment

- Python 3.13.9
- charset-normalizer 3.5.1
- ruamel.yaml 0.19.1
- Linux x86_64

## Where the bug is

`translation_finder/finder.py`, lines 157–177:

```python
def list_files(self, root: PurePath, files: PathListType, dirs: PathListType) -> None:
    with scandir(root) as matches:
        for match in matches:
            if match.is_symlink():
                continue
            is_dir = match.is_dir()
            path = Path(match.path)
            if any(path.match(exclude) for exclude in EXCLUDES):
                continue
            if is_dir:
                dirs.append(self.process_path(path))
                try:
                    self.list_files(path, files, dirs)  # <-- line 176: unbounded recursion
                except OSError:
                    continue
            else:
                files.append(self.process_path(path))
```

The function calls itself recursively for every subdirectory. Only `OSError` is caught — `RecursionError` escapes and crashes `discover()` / `Finder()`.

## Why it matters

Git fully supports trees that are 1000+ levels deep. Any contributor can push such a tree to a repository. When Weblate scans that repo (import, update, webhook, PR), the discovery task crashes. Every retry also crashes, so the component's translation activity stops.

## Steps to reproduce

1. Run the PoC script:
   ```bash
   python3 poc_deepnest.py 1000
   ```
2. The script creates a tree with 1000 nested directories plus two tiny translation files.
3. It calls `discover()` on the tree.

## Result (measured, repeatable)

| Depth | Result |
|---|---|
| 960 | pass — no crash |
| 985 | pass — no crash |
| **990** | **CRASH — RecursionError** |
| 1000, 1050, 1100 | CRASH |

The exact boundary is ~960–1000 depending on Python version and stack. Below it works, above it always crashes.

## Suggested fix

**Best:** Replace recursion with an iterative walk (`os.walk()`), or add a depth cap (~256).

**Minimum:** Catch `RecursionError` and skip that subtree:

```python
try:
    self.list_files(path, files, dirs)
except (OSError, RecursionError):  # add RecursionError here
    continue
```

This is a one-line fix that turns the crash into a skip.
