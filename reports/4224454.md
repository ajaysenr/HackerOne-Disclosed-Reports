## Vulnerability Details

## Summary:
Setting CURLOPT_RESOLVE stores the application's curl_slist pointer in an
internal handle field that curl_easy_reset() does not clear, so after the
application frees its list, the next curl_easy_perform() on the reset handle
reads the freed memory while parsing the resolve entries. Freeing the list at
that point follows the documentation: CURLOPT_RESOLVE(3) states the list is
not copied and must be kept around only until after the transfer has
completed, and curl_easy_reset(3) states all options previously set on the
handle are re-initialized to their default values, the state the handle had
when created.

## Affected version
curl 8.23.0 built from the upstream curl-8_23_0 source on Linux x86_64:
clang -O1 + ASan reports the heap-use-after-free below, and a gcc -O2 native
build crashes with SIGSEGV (exit 139) on the same sequence.

## Steps To Reproduce:
Build curl 8.23.0 with ASan, compile the PoC against that build and run it;
no network access is needed because the freed list is parsed during
Curl_pretransfer, before any connection is attempted.
```
    cmake -B b -DCMAKE_BUILD_TYPE=Debug \
          -DCMAKE_C_FLAGS="-fsanitize=address -g -O1" && cmake --build b -j
    gcc -fsanitize=address poc.c -o poc -I<curl-src>/include -Lb/lib -lcurl
    ./poc
```

poc.c:
```
    /* curl 8.23.0 - curl_easy_reset() does not clear the internal
     * state.resolve alias of the CURLOPT_RESOLVE list. */
    #include <curl/curl.h>
    int main(void)
    {
      CURL *h = curl_easy_init();
      struct curl_slist *resolve =
        curl_slist_append(NULL, "host-a.invalid:59998:127.0.0.1");
      curl_slist_append(resolve, "host-b.invalid:59998:127.0.0.1");
      curl_slist_append(resolve, "host-c.invalid:59998:127.0.0.1");
      curl_easy_setopt(h, CURLOPT_URL, "http://host-a.invalid:59998/");
      curl_easy_setopt(h, CURLOPT_RESOLVE, resolve);
      curl_easy_reset(h);            /* doc: handle back to as-created state */
      curl_slist_free_all(resolve);  /* app frees its own list */
      curl_easy_setopt(h, CURLOPT_URL, "http://host-a.invalid:59998/");
      curl_easy_perform(h);          /* UAF read during Curl_pretransfer */
      curl_easy_cleanup(h);
      return 0;
    }
```

## Impact

## Summary:

This is a use-after-free read inside libcurl, reached through documented API
usage, that reliably crashes the process in a native -O2 build, affecting any
application that resets easy handles and frees its CURLOPT_RESOLVE lists.
