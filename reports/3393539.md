## Vulnerability Details

## Summary:
When handling NTLMv2, if the decoded type-2 “TargetInfo” is large enough that `ntresplen+header_size` exceeds `NTLM_BUFSIZE` (1024), the code returns early without freeing `ntlmv2resp`, causing a memory leak.

https://github.com/curl/curl/blob/7d5d0645e5562f65005488fbc7fd270a71239a5f/lib/vauth/ntlm.c#L789

Security Impact: Low
A malicious peer can set TargetInfo to be above the threshold and cause the client to leak memory. With repeated connections, this can gradually exhaust the resources of the client.

This vulnerability was found using Theori's Xint Code (an AI-powered tool), but validated and confirmed by our human researchers.

## Affected version
Affects the latest version, 8.16.0
