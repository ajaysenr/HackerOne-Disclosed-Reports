## Vulnerability Details

## Summary:
An authenticated low-privilege user can register a push device with an attacker-controlled `proxyServer` through `POST /ocs/v2.php/apps/notifications/api/v2/push`
Later, when a notification is triggered for that user, the backend performs a server-side POST request to `{proxyServer}/notifications`.
This creates an SSRF primitive (server-side outbound request) to attacker-chosen targets, including localhost/internal services.

##Version:
==Notifications app: 5.0.0==

##Code:
```
- notifications-master\lib\Controller\PushController.php (accepts user proxyServer, NoAdminRequired route)
- notifications-master\lib\Push.php (sendNotificationsToProxies(), server-side POST $proxyServer.'/notifications')
```

## Steps To Reproduce:
1. Log in as a normal user (e.g., yoyo) and create an app password.
2. Register a push device using OCS push API with:
- valid `pushTokenHash`
- valid `devicePublicKey`
- `proxyServer=http://localhost/`
3. Trigger a push event for that user (`occ notification:test-push yoyo --files`).
4. Check server logs and observe internal outbound request from backend:
- POST /notifications
- source 127.0.0.1
- UA Nextcloud Server Crawler

5. Observed Evidence (from your run)
- Push registration returned HTTP/1.1 201 Created.
- Log line confirms backend SSRF request:
- 127.0.0.1 ... "POST /notifications HTTP/1.1" ... "Nextcloud Server Crawler"
