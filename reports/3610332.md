## Vulnerability Details

## Summary:
The approval workflow includes a protection intended to prevent an approver from approving or rejecting a file whose contents changed after review, using the file etag. However, the backend only enforces this check when the etag parameter is present and non-empty. An attacker can intercept the request from the UI, remove the etag field, and successfully approve or reject a file even after it was modified.

This breaks the integrity of the approval process because the approver may approve a different file state than the one they reviewed.
##Prerequisites

A valid approval workflow exists.
test1 is allowed to request approval.
test2 is allowed to approve.
test2 has access to the pending file.

## Impact

This vulnerability allows bypassing the content freshness protection in the approval workflow. In practice, it can lead to:

- Approval of a file version different from the one reviewed
- Loss of integrity in internal sign-off or approval processes
- Approval of altered compliance, legal, financial, or release artifacts
- Abuse by a requester who modifies the file after review but before final approval
If this app is used in sensitive approval workflows, the impact may be higher depending on deployment context.
