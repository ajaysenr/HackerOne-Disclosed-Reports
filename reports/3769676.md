## Vulnerability Details

Any authenticated user with basic SELECT privileges can crash the entire MariaDB server process by passing a deeply nested GeoJSON GeometryCollection to `ST_GeomFromGeoJSON()`. The crash kills all active connections and requires a full server restart. The root cause is unbounded recursion in the GeoJSON parser (`sql/spatial.cc`) with zero stack overflow guards, while the equivalent JSON parsing functions have nine such guards. The WKT parser explicitly rejects nested GeometryCollection objects, confirming that the developers recognized the recursion risk but never applied the same defense to the GeoJSON code path.

## Vulnerability Details

MariaDB's `ST_GeomFromGeoJSON()` function parses GeoJSON input through a recursive call chain between two functions:

1. `Geometry::create_from_json()` at `sql/spatial.cc:578`
2. `Gis_geometry_collection::init_from_json()` at `sql/spatial.cc:4447`

When a GeometryCollection contains another GeometryCollection, `init_from_json()` calls `create_from_json()` for each nested geometry (line 4474), which identifies the inner GeometryCollection and calls `init_from_json()` again. This loop repeats without limit.

Each recursion level consumes roughly 300 to 500 bytes of C stack space. With the default `thread_stack` of 256KB to 1MB, approximately 650 to 2500 levels of nesting will exhaust the stack and trigger a SIGSEGV, crashing the entire `mysqld` process.

### Why existing protections do not help

**JSON parser depth limit (32) is bypassed.** At line 754 of `spatial.cc`, `create_from_json()` calls `json_scan_start()`, which resets the JSON engine's `stack_p` counter to 0 on every recursive call. The depth limit never accumulates.

**No `check_stack_overrun()` anywhere in spatial.cc.** A grep confirms zero occurrences. Compare this with `sql/item_jsonfunc.cc`, which has nine `check_stack_overrun()` guards protecting its own recursive JSON processing.

**The WKT parser blocks this exact pattern.** At `spatial.cc:4337-4341`, `Gis_geometry_collection::init_from_wkt()` explicitly rejects nested GeometryCollection with the error "Unexpected GEOMETRYCOLLECTION". The GeoJSON parser has no equivalent guard.

This is a textbook variant miss: the same recursion risk was identified and mitigated in two parallel code paths (JSON functions and WKT parser), but the GeoJSON parser was left unprotected.

## Steps to Reproduce

This is a source code finding based on review of the MariaDB Server GitHub repository (branch: main, version 13.1.0-alpha). The vulnerable code has been present since `ST_GeomFromGeoJSON` was introduced in MariaDB 10.2.4 and affects all versions through the current development trunk.

**1.** Connect to a MariaDB server as any user with SELECT privilege.

**2.** Generate a deeply nested GeoJSON GeometryCollection. The following Python script produces a payload with 2000 nesting levels:

```python
payload = '{"type":"Point","coordinates":[0,0]}'
for i in range(2000):
    payload = '{"type":"GeometryCollection","geometries":[' + payload + ']}'
print(payload)
```

**3.** Execute the query:

```sql
SELECT ST_GeomFromGeoJSON('<paste_nested_payload_here>');
```

**4.** The server process crashes with SIGSEGV (stack overflow). All client connections are terminated. The server must be restarted.

### Additional attack surface

- **Unauthenticated via web applications:** Any application that passes user-supplied GeoJSON data to `ST_GeomFromGeoJSON()` (common in mapping and GIS applications) creates an unauthenticated attack vector against the backend database server.

- **Replication cascade:** If statement-based replication (SBR) is in use, the malicious query replicates to all slaves, crashing them as well. A single query can take down an entire replication topology.

## Affected Versions

All MariaDB versions from 10.2.4 (when `ST_GeomFromGeoJSON` was introduced) through 13.1.0-alpha (current development trunk). The recursive call chain in `spatial.cc` has never had stack overflow protection added.

## Recommended Fix

Add `check_stack_overrun(current_thd, STACK_MIN_SIZE, NULL)` at the entry of `Gis_geometry_collection::init_from_json()` (line 4447 of `sql/spatial.cc`), matching the pattern used throughout `sql/item_jsonfunc.cc`. Alternatively, or additionally, reject nested GeometryCollection in the GeoJSON path the same way the WKT path does at lines 4337-4341.

## Impact

A single authenticated user with the most basic privilege level (SELECT) can crash the entire MariaDB server with one query. This is not a per-connection crash. MariaDB uses a single-process, multi-threaded architecture, so a stack overflow in any thread kills the entire `mysqld` process. Every connected client loses their session. Uncommitted transactions are rolled back. The server requires a manual restart (or automatic restart via systemd, but with a downtime window).

The attack payload is small (under 1MB for 2000 nesting levels) and can be repeated immediately after the server restarts, enabling sustained denial of service.
