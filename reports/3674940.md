## Vulnerability Details

## Summary

An `API/REST only` delegated admin can bypass folder-level authorization and gain access to **any Team Folder** by abusing:

```http
POST /index.php/apps/groupfolders/folders/{id}/groups
```

Because `folder_id` is predictable (auto-increment), an attacker can **enumerate all Team Folders and mass-assign their own group**, resulting in full access to organization-wide data.

## Affected Endpoint

```http
POST /index.php/apps/groupfolders/folders/{id}/groups
```

## Tested Environment

* Nextcloud Hub 26 Winter (33.0.2)
* Deployment: Docker (local)
* Groupfolders app: latest compatible version
* Workspace app: enabled

## Preconditions

* Team Folders app enabled
* Workspace app enabled
* Attacker has `API/REST only` delegated admin privileges
* Attacker controls a group (e.g. `Product_Dev`)

## Steps to Reproduce

### Single Folder Exploit

1. Log in as an attacker account with `API/REST only` delegated admin privileges

2. Use a proxy tool (e.g. Burp Suite) to intercept a request and obtain:
   * Session cookie
   * `requesttoken` (CSRF token)

3. Identify a Team Folder not managed by the attacker (e.g. `Finance`, id=`1`)

4. Send the following request:

```http
POST /index.php/apps/groupfolders/folders/1/groups
Host: <target>
Cookie: <session_cookie>
requesttoken: <request_token>
Content-Type: application/json

{"group": "Product_Dev"}
```

5. Observe that the request is accepted and the group is successfully added to the target folder

6. Log in as a user in `Product_Dev` (or refresh mounts)

7. Navigate to Files UI

8. Observe that the `Finance` Team Folder is now visible and accessible

### Mass Exploitation (Full Instance Compromise)

1. Using the same authenticated session (cookie + requesttoken)

2. Enumerate folder IDs (e.g. sequential integers: 1–100)

3. Repeat the request:

```http
POST /index.php/apps/groupfolders/folders/{id}/groups
```

4. Add attacker-controlled group (`Product_Dev`) to each folder

5. Result:
   * Multiple Team Folders become accessible
   * Cross-team data exposure achieved

## Expected Result

The API should return `403 Forbidden` unless the caller is authorized to manage the specific Team Folder.

## Actual Result

The API allows modification of folder access based solely on API-level privileges, without enforcing folder-level authorization.

## Additional Notes

* Folder IDs are auto-increment, making enumeration trivial
* No rate limiting or authorization checks prevent mass exploitation
* The issue affects write endpoints responsible for access control

## Impact

This vulnerability allows an attacker to:

* Enumerate all existing Team Folder IDs
* Add an attacker-controlled group to each folder
* Gain access to **all Team Folders across the instance**
* Read, download, and interact with sensitive files

This leads to:

* Organization-wide data exposure (Finance, HR, Legal, Engineering, etc.)
* Complete breakdown of Team Folder isolation
* Privilege escalation from limited delegated admin → global data access

## Attack Scenario

An attacker with limited delegated admin privileges can:

1. Enumerate all Team Folder IDs
2. Add their own group to each folder
3. Instantly gain access to all organizational data

Example:

* Access Finance → download financial reports
* Access HR → retrieve employee data
* Access Engineering → access source code or internal documents

This enables **large-scale data exfiltration with a single low-privileged account**.
