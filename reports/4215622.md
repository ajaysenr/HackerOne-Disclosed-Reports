## Program Summary

> ## Description

HackerOne community member Prakhar Porwal reported that an unauthenticated caller could submit a variable for one tracker while naming a conversion produced by another tracker. The public variable-logging endpoint did not verify that the conversion belonged to the supplied tracker, and maintenance attached queued values using only the conversion ID and server identifier. A unique variable from the first tracker could then be attached to the second tracker's conversion and cause it to be marked as a duplicate, excluding it from conversion reports. Values submitted for a tracker's own conversions remain client-supplied by design.

## Resolution

Variable logging now verifies that the named conversion belongs to the supplied tracker. Maintenance migrates a queued variable value only when the variable belongs to the conversion's tracker, and duplicate detection applies the same check to values already migrated.

Security advisory: https://www.revive-adserver.com/security/revive-sa-2026-005
