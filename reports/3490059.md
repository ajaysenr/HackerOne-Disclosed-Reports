## Program Summary

> The Text app, which also handles attachments in Notes, did not remove the Unicode right-to-left override character (U+202E) from the names of attached files. An attacker could attach a file whose name was displayed in a misleading way, for example an executable that looks like a PDF, and trick other users into downloading and opening it.

The right-to-left override character is now removed from attachment names.

Fixed in Nextcloud Server 32.0.7 and 33.0.1, and in Nextcloud Enterprise 29.0.16.13, 30.0.17.8 and 31.0.14.3.

## Vulnerability Details

## Product

Nextcloud – Notes app

---

## Vulnerability Type

Improper handling of Unicode bidirectional control characters (RTLO) in filenames
(CWE‑116: Improper Encoding or Escaping of Output)

---

## Description

Nextcloud Notes allows uploading files containing Unicode **Right‑To‑Left Override (RTLO – U+202E)** characters in their filenames.
These characters are invisible and can be abused to manipulate how filenames are interpreted or trusted by users.

Although the Notes UI displays the filename in logical order, the application **still allows executable files (`.exe`) to be uploaded and downloaded without restriction**, which may mislead users into trusting and opening dangerous files.

---

## Steps to Reproduce

1. On a Linux system, create a filename containing an RTLO character:

   ```bash
   touch "invoice$(printf '\u202E')fdp.exe"
   ```

2. Verify the filename:

   ```bash
   ls
   ```

   The file appears as:

   ```
   invoicefdp.exe
   ```

3. Upload the file to **Nextcloud Notes** as an attachment.

4. Observe the filename in the Notes UI:

   ```
   invoicefdp.exe
   ```

5. Download the file from Notes.

6. Observe that the downloaded file retains the **`.exe` extension**.

---

## Expected Result

* Filenames containing Unicode bidirectional control characters should be sanitized or rejected.
* Executable files should be clearly marked, restricted, or blocked.
* Users should not be exposed to potentially dangerous file types through Notes.

---

## Actual Result

* RTLO characters are allowed in filenames.
* Executable files (`.exe`) can be uploaded and downloaded.
* The filename contains invisible control characters that may confuse users or downstream systems.

---

## Impact

An attacker can upload executable files with manipulated filenames that may appear harmless to users or automated systems.
This can lead to **social‑engineering attacks**, where users are tricked into downloading and executing malicious files.

While no direct code execution occurs on the server, this poses a **user‑level security risk**, especially in collaborative environments.

---

## Proof of Concept

Filename used:

```
invoice<U+202E>fdp.exe
```

Command used:

```bash
touch "invoice$(printf '\u202E')fdp.exe"
```

---

## Security Risk

**Medium**

* Requires user interaction
* Can lead to malware execution on user systems
* Known attack technique used in phishing campaigns

---

## Recommendation

* Strip or escape Unicode bidi control characters from filenames.
* Reject or warn on executable file uploads.
* Normalize filenames before display and download.
