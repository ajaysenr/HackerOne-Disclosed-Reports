## Program Summary

> Advisory: https://github.com/nextcloud/security-advisories/security/advisories/GHSA-5gv7-hw69-w6px

## Vulnerability Details

When an attacker accesses a shared filter-based smart album owned by another user, the system uses the **attacker's** `photosSourceFolders` configuration to determine which paths are searched in the **victim's** folder. By configuring more permissive paths than the victim intended, an attacker can expand the search scope to include folders the victim didn't configure, potentially discovering files that match the album's filters but exist in paths outside the victim's intended photo source folders.

**This is a High vulnerability** leading to **unauthorized information disclosure** where files in unintended folders can be discovered and accessed through the shared album.

## Vulnerable Code

**File:** `lib/Filters/FiltersManager.php`  
**Lines:** 88-98

```php
private function getPhotosDefaultSearchConditions(): array {
    $folders = json_decode($this->userConfigService->getUserConfig('photosSourceFolders'));  
    //  High: Gets Attacker's config but searches in victim's folder
    
    return [
        new SearchBinaryOperator(

            ), $folders)
        ),
        // ...
    ];
}
```

**File:** `lib/Filters/FiltersManager.php`  
**Lines:** 45-68

```php
public function getFilesBasedOnFilters(string $userId, array $userFilters, ?int $fileId = null): array {

```

**Path Validation Issue:** `lib/Controller/ApiController.php:89-102`

```php
private function validatePath(mixed $path): bool {
    if (!is_string($path)) {
        return false;
    }
    
    if (!str_starts_with($path, '/')) {
        return false;
    }
    
    if (str_contains($path, '..')) {
        return false;
    }
    
    return true;  //  Root path "/" is allowed!
}
```

**The Critical Issue:**
- Path validation allows root path `"/"` 
- When `folder = "/"`, the pattern becomes `'files' . '/' . '/%'` = `'files//%'` (potentially matches all files)
- Attacker can set multiple paths: `["/Photos", "/Documents", "/Private", "/Backup"]`
- If victim only configured `["/Photos"]`, attacker's expanded paths search additional folders

## Attack Flow

```
1. Victim Config: photosSourceFolders = ["/Photos"]
   Victim shares album with attacker

2. Attacker Config: photosSourceFolders = ["/Photos", "/Documents", "/Private"]

3. Attacker requests: GET /apps/photos/api/v1/preview/{fileId}

4. PreviewController::getFileIdForAlbums()
   └─> Calls getFilesBasedOnFilters("victim", filters, fileId)

5. FiltersManager::getFilesBasedOnFilters("victim", ...)
   └─> getPhotosDefaultSearchConditions()
       └─> getUserConfig('photosSourceFolders')
       └─>  Returns ATTACKER's config: ["/Photos", "/Documents", "/Private"]

6. Search Query Built:
   WHERE (album_filter) 
     AND (path LIKE 'files/Photos/%' 
          OR path LIKE 'files/Documents/%'       EXPANDED!
          OR path LIKE 'files/Private/%')        EXPANDED!

7. Search Executed in VICTIM's folder:
   getUserFolder("victim")->search($query)
   
8. Results Include:
    /Photos/file.jpg (authorized)
    /Documents/secret.jpg (unauthaurized- victim didn't configure /Documents!)

9. Attacker can access unauthorized files through shared album preview/download
```

## Attacker Requirements

- Valid Nextcloud user account (any authenticated user)
- Access to at least one shared filter-based smart album (owned by another user)
- Ability to configure `photosSourceFolders` via API endpoint `/apps/photos/api/v1/config/photosSourceFolders`
- Victim has files in folders outside their configured `photosSourceFolders` that match the album's filters

## Steps to Reproduce

### Prerequisites:
1. **Victim** configures `photosSourceFolders = ["/Photos"]`
2. **Victim** has files in `/Photos` folder (intended) AND `/Documents` folder (unintended)
3. **Victim** shares folder/album with **Attacker**

### Attack Steps:

**Step 1: Attacker configures expanded paths**
```bash
PUT /apps/photos/api/v1/config/photosSourceFolders
Content-Type: application/json

{
  "value": "[\"/Photos\", \"/Documents\", \"/Private\", \"/Backup\"]"
}
```

**Step 2: Attacker accesses shared album**
```bash
GET /apps/photos/api/v1/preview/{fileId}?x=256&y=256
```

**Step 3: Observe unauthorized file discovery**
- System searches in victim's `/Documents`, `/Private`, `/Backup` folders
- Files in these folders are included in results
- Attacker can preview/access files victim didn't intend to share

### Vulnerability Confirmation

#### Confirmed Behaviors:

1. **Unauthorized File Discovery:**
   - Victim configured: `photosSourceFolders = ["/Photos"]`
   - Victim shared: `/Photos` folder only
   - Attacker expanded to: `["/Photos", "/Documents"]`
   - **Result: Attacker successfully accessed `secret.jpg` from `/Documents`** (Unauthorized)

2. **Configuration Bypass:**
   - Even with attacker config set to `["/Photos"]` (matching victim)
   - **Result: Still successfully accessed files from `/Documents`** (Unauthorized)

3. **Root Path Exploitation:**
   - Setting `photosSourceFolders = ["/"]`
   - **Result: Successfully accessed ALL folders in victim's account** (High)

4. **Multiple Successful Downloads:**
   - 5 separate file downloads from unauthorized location
   - Consistent exploitation across different configurations

## Proof That There Is No Mitigation

1. **No path scope validation:** The system doesn't verify that search paths match the album owner's configuration
2. **No authorization check:** No validation that requesting user's paths should be applied to another user's folder
3. **Path validation allows expansion:** Root path `"/"` and any valid path prefixes are allowed
4. **No folder restriction enforcement:** Album owner's folder restrictions are not enforced during search

## Impact

1. **Unauthorized File Discovery:** Attacker can discover files in folders the victim didn't configure for photo search
2. **Information Disclosure:** Files in private folders can be discovered, metadata exposed, preview thumbnails may reveal sensitive content
3. **Privacy Violation:** Victim's folder structure probed, existence of private folders revealed
4. **Trust Boundary Violation:** Album sharing assumes files come only from configured source folders

**Why This Is HIGH:**
- **Real Data Exposure:** Files in unauthorized folders can be discovered and accessed
- **Bypass of Intentional Restrictions:** Victim explicitly configured limited paths but attacker expands scope
- **Practical Exploitability:** Requires only access to shared album + ability to configure own `photosSourceFolders`
